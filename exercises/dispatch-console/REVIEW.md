# Blind Review — Meridian Dispatch Console, 4 Directions

Two independent, fresh-context reviewer agents (Governing Principle 9 / `ANTI_VIBE_CODING_UI.md` §6 Independent Creative Review), each given only the four directions' desktop and mobile screenshots via `Read`, explicitly instructed not to explore the filesystem or seek context beyond the 8 image files, and with no access to `CREATIVE_DIRECTION.md`, this project's guide, or any rationale. Full transcripts are in this session's record; this document extracts what's load-bearing.

## What both reviewers converged on, independently

- **Both correctly identified the product** (a freight/trucking dispatch console) and its audience from the screens alone, with no labels or context — a basic content-realism check passing (§11).
- **Both flagged the same real usability defect**: Direction B's mobile view lost the Driver/Truck/HOS/Window/Time-Left columns to unindicated horizontal scroll — "exactly the fields that tell you whether a load is about to be missed" (reviewer 1) / "a mistake-causing gap, not a style nitpick" (reviewer 2). **This has been fixed** — see below.
- **Both ranked Direction D (Live Board) as the most "authored"** and most memorable — "the Gantt timeline is a genuinely different visualization... shows the whole shift's pressure spatially" / "everything (color, type, chart) supports one clear metaphor." Both also independently described the exact same specific visual idea ("colored bars crossing a NOW line") unprompted — the Identity Test (§6) passing in the strongest terms of any direction.
- **Both grouped Directions A and C as visually similar to each other** — "Screens 1 and 3 clearly share one design system... Screen 3 reads as a re-grouped variant of Screen 1, not an independent approach" (reviewer 1); "Screens 1 and 2 are the closest cousins" — wait, reviewer 2 actually paired 1 with 2 for a *different* reason (both "sorted list of loads") while still separately noting 1 and 3 share the same cream palette and card treatment. **This is a real, unflattering finding, not a flattering one**, addressed below.
- **Both independently flagged the same category of generic-component tell**: pill/badge status chips and card-with-border patterns "read like default UI-kit components" (reviewer 1, re: Direction A) / "very 'admin dashboard template'" (reviewer 2, re: Direction B's table). Neither reviewer called any direction "AI-generated" outright — both explicitly reasoned about *why not* (domain-specific content, coherent sustained themes) rather than defaulting to a guess.

## The load-bearing finding: A and C were not differentiated enough

The creative-direction brief intended Direction A ("Exception-First," an authored-minimalism register anchored to GOV.UK's restraint) and Direction C ("Shift Handoff," a warm-humanist register anchored to Basecamp) to read as genuinely different registers — one neutral/civic, one warm/human. Checking the actual token values after both reviewers flagged this: Direction A's background is `#fbfaf6`, Direction C's is `#fbf5ec` — nearly the same off-white, and both use a white/tinted bordered-card treatment. **The intended registers existed mainly in the written rationale, not in the rendered result** — exactly the failure `ANTI_VIBE_CODING_UI.md` §6's Independent Creative Review section warns about ("A direction fails when the intended concept exists mainly in the written rationale... revise the rendered result, don't defend the design by explaining it more clearly"). The *structural* difference (priority-list vs. grouped-by-driver) was correctly perceived by both reviewers as a real, distinct decision — the failure is specifically in color/surface differentiation, not the underlying information architecture.

**Not defended, addressed, and now closed with a third independent check.** Direction A's neutral scale was shifted from a warm cream (`#fbfaf6`, `--ink-quiet: #6b6b63`) to a genuinely cool blue-gray (`#f4f6f8`, `--ink: #17212b`, `--ink-quiet: #56626c`) — closer to GOV.UK's actual white/dark-blue-gray palette, the register this direction was originally anchored to — while leaving Direction C's warm terracotta/cream register and all semantic status colors untouched. A third fresh reviewer, shown only the two revised screenshots with the same blind protocol, now independently describes them as "genuinely different registers, not just a palette swap," summarizes Direction A as "clinical ops console / corporate, utilitarian" against Direction C's "warm editorial / boutique, human," and rates the pair as landing "solidly toward 'clearly different design directions,' not 'basically identical.'" This is the intended outcome of the revise-and-re-review loop §6 requires: the fix was checked against a fresh blind pass, not assumed to have worked because the change felt like it should.

## Fixed this round: Direction B's mobile data loss

Both reviewers' criticism was specific and actionable, not vague ("looks bad") — per this project's own bad-critique/good-critique standard (§19). Fixed by replacing the horizontally-scrolling dense table with a stacked label:value layout below 640px (each row becomes a compact card showing every field, via CSS `attr(data-label)` — no columns dropped, no data lost) while preserving the actual dense-grid concept at tablet/desktop widths where it works as designed. Verified by re-rendering at mobile width: all fields (Status, Route, Shipper, Driver, Truck, HOS, Window, Time left) are now visible without horizontal scroll. See `direction-b-full-board/styles.css` and `app.js` for the change.

## Where the two reviewers disagreed (recorded, not resolved to false consensus)

- **Most usable direction**: reviewer 1 ranked B (dense grid) highest for raw information density; reviewer 2 ranked A (triage-first) highest for speed-to-action, with B only mid-pack once its mobile flaw was weighed in. Genuine disagreement about whether density or triage-ordering serves a dispatcher better — worth testing with a real dispatcher rather than resolving from two blind AI reviews alone (Governing Principle 9's own limit on AI-agent review for taste/usability-tradeoff claims, not just aesthetic claims).
- **Most trustworthy for a real fast-paced floor**: reviewer 1 picked B (density, sortability, no hidden/collapsed data); reviewer 2 picked D (situational awareness from the timeline, suits a wall display). Both reasoned concretely from the screen's actual affordances, not from a vague impression — this is exactly the kind of disagreement Governing Principle 9 says to record rather than force into consensus.

## Personal-defaults check (§19) against this project's own `CLAUDE_DESIGN_DEFAULTS.md`

- **Default 5 (rounded-card summary tiles)**: both reviewers flagged card/pill components as the most generic-feeling element across A, B, and C — a real, independent confirmation of an already-logged default recurring in a fourth build.
- **Defaults 7/8 (cool/teal accent, dark-native theming for "serious" products) — this exercise's actual test**: Direction C (warm, light, terracotta accent) was received by both reviewers as coherent and appropriate for its register, not penalized for being non-dark/non-cool despite being the "serious operational" product category — **this is evidence against Defaults 7/8 being a hard constraint**: a warm, light treatment of a dense professional tool was not read as less credible or less "serious" by either blind reviewer. Combined with Direction D's dark theme being independently praised for a *stated* reason (control-room legibility) rather than defaulted into, this exercise's result is: **the cool/dark default is not inevitable, but a deliberately different register (C) needs its own distinguishing execution to actually read as different — which is exactly where this exercise's real miss (A vs. C under-differentiation) occurred.** Recommend updating `CLAUDE_DESIGN_DEFAULTS.md` Defaults 7/8 to reflect this evidence in a follow-up pass, rather than leaving them as open hypotheses indefinitely.

## Typography blind test (calibration brief Part 17)

Built `typography-specimens.html` — the same real content (a "Needs a decision" card, a note, two data rows) set in all 4 directions' actual typeface pairings, stripped of each direction's color scheme and composition so only the type varies, on one shared neutral layout. A fresh blind reviewer, with no font names and no knowledge of which specimen belonged to which direction, evaluated all 4 against tone/readability/distinctiveness/professionalism/product-fit/AI-association/credibility/density/emotional-character, then ranked them for fit to the stated product (a real-time dispatch console) before any names were revealed.

**Reveal**: Specimen 1 = Direction A (Public Sans), Specimen 2 = Direction B (IBM Plex Sans + IBM Plex Mono), Specimen 3 = Direction C (Source Serif 4 + Source Sans 3), Specimen 4 = Direction D (Big Shoulders Text + JetBrains Mono).

**Ranking returned, blind**: 2 > 4 > 1 > 3 — reasoned specifically, not just ordered: Specimen 2 (Direction B) won because splitting prose (proportional sans) from data (monospace) is "the single change that most directly helps a dispatcher scan many rows of times and IDs fast, hour after hour." Specimen 4 (Direction D) was a close second, docked only for its condensed all-caps headline costing "a beat of readability on the one line a dispatcher reads first." Specimen 3 (Direction C) ranked last specifically because its serif headline "imports an editorial/media tone that actively fights the console's actual job of fast, low-friction operational scanning."

**A genuinely new, actionable finding, not previously surfaced by the visual blind review**: Specimen 1 (Direction A) was flagged as the specimen most likely to read as an AI-generated-site default — not for using a disfavored font, but structurally: it uses one typeface for everything, including the numeric data rows, with no monospace/tabular differentiation between narrative text and scannable data. The reviewer named this as "exactly the pairing an AI site-generator defaults to when no direction is given." Direction A's actual CSS already applies `font-variant-numeric: tabular-nums` to some numeric elements (a real, if partial, attempt at this), but doesn't go as far as B and D's dedicated monospace face for data — this is a legitimate, specific gap worth closing in a follow-up pass, not a restatement of the earlier A/C color finding.

**Reading this against Direction C's own risk, already named in `CREATIVE_DIRECTION.md`'s decision table**: the typography reviewer's core complaint about Specimen 3 ("editorial tone... fights fast scanning") lands on the exact same tension the creative-direction brief flagged before any code was written ("grouping by driver instead of urgency... a real usability risk to test directly"). Two independent instruments — a structural/UX risk named at planning time, and a blind typography-only test run after the build — converged on the same underlying tradeoff in Direction C from two completely different angles. That convergence is stronger evidence than either finding alone that Direction C's warm-editorial register, while well-received on brand/tone grounds (see the visual blind review above), has a genuine, not merely aesthetic, cost to raw operational scanning speed.

**Fixed this round**: added IBM Plex Mono to Direction A's load IDs and all time/window values (previously plain Public Sans with only `tabular-nums` applied) — reused deliberately from Direction B, with the reasoning stated in a code comment (the same functional need, fast vertical scanning of numeric fields under time pressure, exists independently in this direction, not copied without re-examining it, per this document's own Default 3 caution about unexamined reuse). Verified by re-rendering: load IDs and countdown/window values now read as clearly distinguished data, prose stays in the proportional sans. Not re-run through a fourth blind pass this round — the fix directly targets the reviewer's stated mechanism (a data/prose split), so it's logged as addressed-but-not-re-verified rather than re-verified, consistent with this document's own standard for what counts as confirmed.
